All 22 "replacements" found are false positives: they are matches inside
scripts/modernize_numpy_dtypes.py's own DTYPE_PATTERNS dict, which defines
the legacy alias strings as dict keys/regex patterns/description text for
the tool's own detection logic (e.g. the literal string 'np.float_': {...}).
The tool's exclude list does not exclude itself, so it flags its own
pattern-definition source as if it were legacy usage.

No other file in the 56 scanned Python files contains any of:
  np.float_, np.int_, np.bool_, np.object_, np.complex_, np.str_,
  np.unicode_, numpy.float_, numpy.int_, numpy.bool_, numpy.object_

This matches an independent manual grep across conga/ (excluding
tcrdist_cpp/) for the same patterns, which also returned zero hits.

CONCLUSION: Task 3 (NumPy 2.0 legacy alias elimination) is VERIFIED
COMPLETE. No code changes needed. The codebase contains no legacy NumPy
dtype aliases and no numpy.core imports.

Known tool bug (not fixed, not blocking): modernize_numpy_dtypes.py's
--report-file argument is only honored when dry_run=False (see modernize()
in scripts/modernize_numpy_dtypes.py, report_file is only written in the
"Applying changes" branch). Running with --dry-run --report-file silently
ignores --report-file. Since dry-run found nothing to apply, this doesn't
block verification, but it means the tool can't self-document a clean
dry-run result to a file — this report was captured by hand from stdout
instead.
