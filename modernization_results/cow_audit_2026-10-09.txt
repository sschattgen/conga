MANUAL REVIEW / ANALYSIS (added 2026-10-09)
============================================================

The raw tool output above reports 421 "potential CoW issues" across 25
files (249 HIGH, 172 MEDIUM). Manual review of every distinct code pattern
in this report found ZERO genuine pandas copy-on-write risks. The detector
pattern-matches generic `x[a][b] = value` / `x[a] = value` syntax without
checking whether `x` is actually a pandas DataFrame, which produces a very
high false-positive rate on this codebase. Specifically:

1. The large majority of "chained_assignment" and "ast_analysis" hits are
   subscript assignment into plain Python dicts or AnnData's `.uns`
   container, e.g.:
     adata.uns['conga_results'][table_tag] = results_df
     overall_status['python']['compatible'] = python_compatible
     recommendations['hardware_specific']['gpu'] = "..."
   None of these are DataFrames. `adata.uns` is a dict-like container;
   assigning into nested dict/dict or dict/list structures is unaffected
   by pandas CoW semantics.

2. Several hits are plain dict- or list-indexed references to DataFrames
   the function owns outright (not a view/slice of another DataFrame),
   e.g. conga/tcr_clumping.py:913-915:
     matched_dfs[i][f'{chain}_match_UMI'] = clones
   `matched_dfs[i]` is `matched_dfs.append(db_tcrs_df[...].copy())` from
   line 893 -- a DataFrame the function copied and owns. Single-level
   column assignment on an owned DataFrame via list/dict indirection is
   CoW-safe; it is equivalent to `df = matched_dfs[i]; df[col] = value`.

3. The "query_chaining" and "mixed_indexing" pattern-type hits (lines
   102 and 128 of the audit report) are matches against comments inside
   scripts/audit_cow_patterns.py's OWN source code
   (`# Pattern 2: Query chaining (df.query(...)[col] = value)`), i.e. the
   tool flagged its own docstrings/comments as issues. The tool's exclude
   list does not exclude itself.

4. The one hit that references real `.loc`-based assignment,
   conga/plotting.py:1868-1872 (`results.loc[missing_epitope,'db_epitope']
   = ...`), is ALREADY using the correct, CoW-safe `.loc[mask, col]`
   pattern that the tool itself recommends as the fix. It was flagged only
   because the tool's own "suggested fix" string in its report matched a
   search pattern, not because the code is unsafe.

No instance of the genuinely risky pattern this task targets --
`df[col][mask] = value` chained assignment on an actual pandas DataFrame
that silently no-ops under unconditional CoW -- was found anywhere in
conga/ or scripts/.

CONCLUSION: Task 4 (pandas 3.0 copy-on-write compliance) -- the specific
chained-assignment risk this audit targets -- is VERIFIED CLEAN for
conga/preprocess.py and conga/tcrdist/*.py (the modules task 4.1/4.2 call
out), and no genuine instance exists elsewhere in the package either.
audit_cow_patterns.py itself needs a precision improvement (track variable
provenance / only flag when the base is demonstrably DataFrame-typed, and
exclude its own source file) before its output is usable as a pass/fail
gate; as currently written, every one of its 421 flags is a false positive
on this codebase, so no code changes were made as a result of running it.
inplace=True call sites are reviewed separately (see task 4.4 writeup).
